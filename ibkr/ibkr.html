    Interactive Brokers has no public browser-callable API: TWS and IB Gateway speak a raw TCP protocol, and the hosted Web API needs an OAuth flow with a private key that must never sit in a static page. The supported way for an app like this one is IBKR's Client Portal Gateway — a small Java process you run yourself. It holds the authenticated session and exposes the Client Portal Web API on https://localhost:5000, which this page then reads.

    1. Run the gateway

    1. Download the Client Portal Gateway from IBKR (requires Java 8 or newer).
    2. Unzip it, then start it: bin/run.sh root/conf.yaml — on Windows bin\run.bat root\conf.yaml.
    3. Open https://localhost:5000, accept the self-signed certificate, and log in with your IBKR credentials.

    2. Let this page talk to the gateway

    The gateway only answers browser requests from origins it has been told to trust. Edit root/conf.yaml and allow this page's origin, then restart the gateway: 

    cors:
  origin.allowed:
    - "https://fe19.github.io"
  allowCredentials: true

    Simplest alternative, no CORS at all: copy ibkr.html, ibkr.css, ibkr.js and demo-data.js into the gateway's root/ folder and open them from https://localhost:5000 — then page and API share an origin. If your gateway listens on another host or port, put its API base URL in the Gateway API URL field above.

    3. Connect

    Press Connect. The page calls /iserver/auth/status, /portfolio/accounts, /portfolio/{account}/ledger and /portfolio/{account}/summary, and pings /tickle once a minute so the gateway session does not time out. Everything is read-only — this page never places an order. Note that an active gateway session logs your IBKR user out of other sessions (TWS, IB Gateway, the web portal) and vice versa.
